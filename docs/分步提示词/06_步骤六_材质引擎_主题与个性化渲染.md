## 任务

### 1. MaterialEngine（`core\MaterialEngine.cs` + `ui\components\MaterialBackground.xaml`）

**通道策略**：

| 通道 | 用途 | 说明 |
|---|---|---|
| 模拟通道（默认，全平台基线） | 所有玻璃窗口 | `AllowsTransparency` 圆角 + 后方截屏 + `BlurEffect` + 底色 + 装饰层。Win10/Win11、x86/x64 视觉一致，支持任意圆角 |
| Win11 原生增强（可选） | 大窗口（收纳板/设置窗） | `DWMWA_SYSTEMBACKDROP_TYPE` + `DWMWA_WINDOW_CORNER_PREFERENCE`。**前提：该窗口切到非 `AllowsTransparency` 模式**；任何一步失败 → 自动回退模拟通道并记日志 |
| Win10 composition | 不用于正式窗口 | `SetWindowCompositionAttribute` 仅作实验 API 保留在 `SystemBridge`，默认关闭 |

**1.1 能力探测优先于版本号（未来兼容性硬要求）**
- 先调 DWM API 看 **HRESULT**：失败即回退，不依赖"猜系统版本"。版本号只用于"提前跳过明显不支持的系统"，读 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\CurrentBuild`（不要用 `Environment.OSVersion`，manifest 未声明兼容性时会虚报）。
- **新通道通过注册表接入**：`MaterialChannel` 枚举 + 注册式尝试链（`模拟 → 原生增强`），未来 Windows 新增 backdrop 类型时**只加一个通道实现**，不改现有回退链与调用方。
- **绝不出现黑底**：任何 DWM/截图路径失败都必须落到模拟通道并记日志；回退后视觉允许降级，不允许空窗。

**1.2 必须保持的现有 API 语义（02/05 已在依赖，不许改）**
- `MaterialBackground`：`SetTheme(bool)`、`SetBoardOpacity(double)`（只作用于板底，与 `personal.boardBg` 图的不透明度互不影响）、`SetCorners(CornerRadius)`（方向圆角）、`PlateStroke`（L3 背景图内缩对齐量）、`Material`（本步起为真实材质档）。
- `SquarePlate`：`Material` / `ApplyCustomLayers(Brush?[3])` / `SetTheme` / `PlateSize` / `Chrome` / `BaseMargin` / `HoverOffset` / `RestOffset` / `PlayDissolve` / `PlayRevive` / `OffsetProperty` —— **一律不动**；本步只替换其"底板材质的绘制来源"。
- 悬浮窗三层自定义（预设材质 + 三层图片 + 每层不透明度）已由 05/清单02 落地：**三层错位、hover、消散动画零回归**。

**1.3 模拟通道实现要点**
- 背景快照：窗口位置/尺寸/材质变化**结束时**抓一次（拖动中用冻结帧），`System.Drawing.CopyFromScreen` 抓窗口后方区域 → `Bitmap` → `ImageBrush`。
- 快照之上叠 `BlurEffect`（模糊档 40 > 液态玻璃 25 > 亚克力 18）；再叠底色（主题 tint，α 按材质档）；再叠程序生成 64×64 噪点（亚克力 0.04、模糊无、液态玻璃 0.06）。
- 液态玻璃附加：顶部 1px 内高光 `#66FFFFFF` + 底部内阴影 + 边缘 24px 渐变加深。
- **自拍预防（2026-10-06 实测定论，取代原文的"Opacity=0 隐帧"方案）**：
  - 系统级"把自己从抓屏里摘掉"的 API `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 对本项目窗型**不可用**：`AllowsTransparency` 分层窗上直接返回 FALSE（`GetLastError=8`），仅非分层窗生效（`build\_captest` 实测对比）；
  - 改用**"最后一次可观测"口径**：整屏抓取时跳过本进程全部可见玻璃窗的矩形（`MaterialEngine.VisibleGlassRects`），这些矩形保留帧内旧内容（该处上一次看得见时的样子）——抓屏因此**不需要隐藏自身**，零隐帧、零闪烁；
  - 帧 = **整屏一张**（`WriteableBitmap`，每窗一份），内容由**桌面变更驱动**刷新（见 1.5），不做周期抓屏。
- **取景（2026-10-06 第三次修订）**：本层只是整屏帧上的一扇取景窗——移动/缩放窗口**只改一个 `RenderTransform`**，不重裁位图（旧实现每移动一步都重建 `CroppedBitmap` + 重传纹理 + 重算模糊 = 用户实机反馈的"移动时背景闪烁 + 卡顿"）。
  - **整屏帧必须住在 `Canvas` 里**：WPF 会给"超出父级可用尺寸"的子元素一个**布局裁剪**（按子元素自身坐标系裁到父级大小），再叠上取景用的负向平移，整块内容会被裁掉又移出可视区 → 材质与模糊一起消失（实机表现="模糊材质失效"）。`Canvas` 测量时可用尺寸为无穷，不产生布局裁剪。
  - `Snapshot.Width/Height` 必须显式赋成整屏 DIP 尺寸：默认 NaN（Auto）参与比较恒为 false，早期版本因此从未赋值、元素停在 Auto 尺寸。

**1.4 性能预算（硬指标，超了就算不过）**

| 指标 | 上限 | 复测方法 |
|---|---|---|
| 单次全屏抓取 + 裁剪 + 上屏 | **≤ 40ms** | 首帧耗时打点进日志，取中端核显实测 |
| 几何变化（拖动/缩放/动画）期间抓屏次数 | **0** | 拖动全程日志计数应为 0（2026-10-06 实测 0 次） |
| 空闲期抓屏次数 | **0**（仅桌面窗口视图变化时各 1 次） | 变更驱动：700ms 一次窗口指纹（~0.3ms），指纹变了才抓（2026-10-06 实测空闲 10s CPU 47ms） |
| 取景对齐 | 最佳偏移 **≤1px**（静止与拖动中都要测） | 参考图与玻璃做中位剖面互相关（`build\probe_align2.py`；实测静止 -1px、拖动中 0px） |
| 同时存在的 `BlurEffect` 实例 | **≤ 2** | 与 02 步缩放期 `_resizeBlur` 互斥复用；超出即复用同一实例 |
| 纹理离屏缓存（`RenderTargetBitmap`） | **≤ 12 张且总字节 ≤ 64MB**，LRU 淘汰 | 借 `IconBitmapCache` 的淘汰口径，键含尺寸档 |
| 常驻内存增量（相对本步前稳定态 81MB） | **≤ +30MB** | 开板/切材质 20 次后 `Get-Process` |
| 空闲 CPU | ≈ 0（无动画时不得有抓屏/重绘循环） | 空闲 2 分钟观察 |

**1.5 多条性能规则**
- 只有 **≥2 个可见玻璃窗口**时才共享同一次全屏抓取（一次 `CopyFromScreen` 全屏，各窗口按 geometry 裁剪）。
- **小于 80×80 的窗口（各级菜单）不抓屏**，直接用静态缓存纹理——`GlassPopup` 现有投影+纯色外观升级为材质观感时，走这条。
- 尺寸变更（拖滑轨/拖窗口）过程中用**冻结帧**，落定后再抓一次；不要把抓屏挂在 `SizeChanged` 每帧上。
- **抓屏只由"桌面窗口视图变化"驱动**（`MaterialEngine.DesktopFingerprint`：可见顶层窗口的 (hwnd, 矩形) 集合哈希，**与 z 序无关**——把 z 序算进去会因前台激活噪声退化成"每 tick 都抓"，实测空闲 8s 抓了十几次）。周期整屏抓屏会阻塞 DWM 合成，用户实机反馈是"鼠标每秒卡一下"。

**1.6 材质预览图**
- 用 MaterialBackground 离屏渲染 120×76 缩略图，替换 05 步设置页占位卡【L64】。
- 缩略图走 `IconBitmapCache` 同类解码路径/缓存，**不要新增第二条解码路径**。

**1.7 风格方向**
- 参考 modern-gradient：柔和渐变底、玻璃拟态、大圆角、半透明发丝描边、彩色软阴影；02 步已落占位版（渐变底 + 发丝边），本步延续该方向（2026-08-28 用户反馈）。

### 2. ThemeEngine（`ui\themes\`）

**2.1 资源结构**：`Tokens.xaml`（画刷/尺寸 key，如 `Brush.TextPrimary`、`Brush.Accent`、`Dim.Corner`）+ `Light.xaml` / `Dark.xaml` 两套值；App 级合并字典；所有窗口一律 `DynamicResource` 引用 token。
> **未来兼容性**：新增一套配色/换肤**只需增加一个字典文件 + 注册一行**，不得改动窗口代码。`SettingsPalette`（05 步占位）应退化为"从 token 取值"的薄封装，其**已 Freeze 画刷缓存**（批次九）保留。

**2.2 模式解析**：`light`/`dark` 直接换字典；`auto`=06:00~18:00 亮（`DispatcherTimer` 每分钟查）；`system`=读 `HKCU\...\AppsUseLightTheme`，经 `SystemEvents.UserPreferenceChanged` **即时跟随**。
- **`transparent`**（原文 L28 新增）= 背景板 α 降至 ≈8%（仅留极淡磨砂与 1px 发丝描边勾勒边界），文字/图标切高对比浅色 + 加重 `DropShadowEffect` 保证任意桌面/窗口背景下可读；材质装饰（噪点/高光/内阴影）减到最轻，仍走模拟通道（**不得依赖 DWM backdrop**）。
- **接管 `ThemeResolver` 时保留批次九的缓存与失效链路**：`IsSystemDark()` 走缓存，系统偏好变化经 `InvalidateSystemTheme()` 失效；本步若换成自己的实现，必须提供等价的失效入口，否则"系统切深色即时跟随"会退化为最多 5s 延迟。

**2.3 切换过渡**：`ThemeFade.Transition`（03 步）对每个可见窗口做快照淡出 300ms【L28】。快照 `RenderTargetBitmap` **用完即弃、不缓存**（本步会增加切换频率，不许改成缓存）。

**2.4 各级菜单**：收纳板空白菜单 / 图标菜单 / 分类项菜单 / 悬浮窗快捷按钮条 / 托盘菜单**全部**跟随主题+材质【L16、L22、L75】。

### 3. 托盘菜单自绘化【原文 L73、L75】

- NotifyIcon 右键不再用 WinForms 菜单：复用 **`GlassPopup`**（已有自绘玻璃弹层）弹四项：**偏好设置 / 复位 / 关闭 / 重启**，动作复用 `TrayController` 现有事件（`PreferencesRequested` / `ResetRequested` / `ExitRequested` / `RestartRequested`），**不新增动作链路**。
- 定位到托盘图标几何（`Shell_NotifyIcon` NIF_GETRECT，取不到用光标位置）；失焦即关；Esc 可关。
- 该弹层尺寸小 → 走 1.5 的"小窗口用静态缓存纹理"分支，不抓屏。
- `TrayController` 现有 `I18n.LanguageChanged` 订阅与文案热切换（含 `Dispose` 释放 `ContextMenuStrip`，批次九）在替换后**要么保留、要么等价迁移**，不得留下未退订的静态订阅。

### 4. 悬浮窗三层自定义渲染（现状保持 + 本步接管材质来源）【原文 L66-71】

- 预设方式：三层板共用 `personal.dockCustom.material` 三选一（模拟通道渲染），叠加每层颜色（含 α）。**三层错位/hover/消散动画不变**。
- 自定义图片方式：`personal.dockCustom.images` 上/中/下各一张（副本已由 05 存进 `config\assets`）→ `ImageBrush` cover 裁剪 + 圆角 12 遮罩；无图的层用默认。
- **各层不透明度（2026-10-06 用户要求）**：`personal.dockCustom.opacity`（[上,中,下]，0~100%）**两种模式都生效**
  ——自定义模式乘在层图 `ImageBrush.Opacity` 上；预设模式由 `SquarePlate` 把该值折进
  `MaterialEngine.Fill` 的 α（`SetLayerOpacities`），**材质配方本身（原始预设）不被改写**。
  该值折进画刷而不动 `Border.Opacity`：三板 `Opacity` 归消散/复现动画所有，改基值会被动画顶掉。
  设置页里这三条滑块是**与预设/自定义面板平级的常驻行**（切模式不隐藏），两模式写同一个键。
- **层序映射（2026-10-06 用户口径）**：存储/设置页的三个值按**界面层序** `[上,中,下]` 排，
  而板子的绘制序是 `[front(左上，画在最上), mid, back(右下，画在最下)]`。
  用户实测口径：**视觉上"右下角那一层"才是上层** → `FloatingDock.ApplyDockCustom` 交给板子前把上/下对调
  （`2 - uiSlot`）。**层图与层不透明度共用同一份对调**，否则会出现"图落在某层、不透明度作用在另一层"的错配。
- 立体感：上板 `DropShadowEffect` 最深，逐层减轻，保持"错开叠加"空间感——**注意与 1.4 的 Effect 数量上限协同**（三层阴影是既有效果，计入预算但不得再叠加新 Effect）。
- 图片解码继续走 `IconBitmapCache.GetOrLoad(..., 256)`（已封顶），**不要新增解码路径**。

### 5. 收纳板自定义背景 L3 完整版【原文 L65】

- crop 区域显示 + 圆角遮罩；图片之上叠 10% 主题色遮罩保证文字可读性。
- **z 序（2026-10-06 用户要求改向）**：图片**压在最底**（`CustomBgHost` → `BgShade` → `MaterialBackground` → 内容），
  即"图片在下、主题纯色板/材质盖在它上面"。板底是半透明的（`personal.boardOpacity`），
  背景图要透出来靠的是板底自身的 α；要看清背景图就把"板底不透明度"调低。
  （此前的"图片居中、材质在下"口径作废，见 STEP_LOG 决策 240 的改向记录。）
- 背景图解码已有封顶（`DecodeBackground`，解码宽=所选屏物理宽）+ crop 按 `decodeScale` 换算；`CropPickerWindow` 已有解码封顶（批次九）。本步**复用**，不要重写。
- 每次开板重解码的问题（批次九审计发现）在本步一并处理：**按 (路径 + crop + 不透明度) 缓存解码结果**，设置变更或文件变化才重解。

## 技术指引与坑

- `CopyFromScreen` 用**物理像素**：窗口 WPF 尺寸 × DPI 缩放系数换算，PerMonitorV2 下用**窗口所在屏**的 DPI（`GlassWindow.DpiScaleX/Y` 已提供）。
- `BlurEffect` 是 GPU 加速（非旧 `BitmapEffect`），中低配核显可用；若驱动黑名单导致软件回退卡顿，提供"性能模式"降级（降模糊半径/关噪点），按首帧耗时自动判定一次。
- Win11 判定优先探测 API 返回码（见 1.1）；注册表读 `CurrentBuild` 只作辅助。
- 所有 DWM/截图 P/Invoke 进 `SystemBridge`（唯一归宿），失败路径必须 `try/catch` + 回退，绝不允许黑底窗口。
- 零第三方依赖：**不得引入任何 NuGet/第三方着色器**，只用 WPF 自带 `Effect` + P/Invoke。
- 不用 .NET 9+ API（`net8.0-windows`）；需要的通用能力自行实现（先例：`JsonElement.DeepEquals` 自实现，决策 5）。
