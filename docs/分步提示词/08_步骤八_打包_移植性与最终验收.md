### 1. 程序图标【原文 L74】

**实际落地（2026-10-06，取代原文的"程序化绘制"方案）**：

- `build\makeicon.ps1`：纯 PowerShell + `System.Drawing`，由**素材源图** `assets\CShip.png`（用户提供的产品图；开发期目录为 `素材\CShip.png`）生成——源图非方形 → 先补透明底正方形、居中高质量缩放（不变形）→ 逐尺寸位图。
- 产出**三处同源**：
  - `src\Cship\app.ico` ← csproj `<ApplicationIcon>`（exe 文件图标 / 任务栏 / 任务管理器）
  - `src\Cship\dependencies\resources\icons\app.ico` ← 托盘 `NotifyIcon`
  - `src\Cship\dependencies\resources\icons\app.png` ← 设置-关于页 Logo（512，透明底）
- **帧格式**：16~128 用 DIB(BMP) 帧、256 用 PNG 帧（与既有产物一致）——GDI+ 对**纯 PNG 帧**的 ICO 取帧不完整（实测请求 256 会退化成 128），混合格式可让托盘与 shell 都取到正确帧。
- **将来替换**【L74】：覆盖 `assets\CShip.png` → 重跑 `makeicon.ps1` → 重跑 `build.ps1`。已实测：临时换成任意图重打包后 exe 内嵌图标指纹改变，还原后指纹复原。
- **幂等**：先删旧产物再生成；ICO 在内存组装，全程无中间文件落盘。

> **取舍说明（决策 290）**：原文要求"程序化绘制三层错开方板"，但用户已提供真实产品图 `CShip.png`（步骤 06 附加需求即据此落地）。**观感优先于"脚本自绘"**——用真实素材的图标与产品本体（三层玻璃方板）语义一致，且用户可随时覆盖源图替换。`makeicon.ps1` 因此只负责"源图 → 多尺寸 ICO"的可靠转制，不负责绘图。

### 2. 发布脚本 `build\build.ps1`（**完整版**：self-contained · 离线即用）

核心命令（每个架构一次；实际由 `build\build.ps1` 组装，暂存 `build\_publish\`）：

```powershell
dotnet publish src\Cship -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=false `
  -p:PublishTrimmed=false `
  -p:SatelliteResourceLanguages=en `
  -p:DebugType=none `
  -o build\_publish\x64
# win-x86 同理，-r win-x86 -o build\_publish\x86
```

| 参数 | 作用 | 注意 |
|---|---|---|
| `PublishTrimmed=false` | **必须** | WPF 不支持裁剪，严禁改 `true` |
| `EnableCompressionInSingleFile` | **默认 `false`**；`-Compress` 才开 | 压缩省约 76MB 体积，但**常驻内存 +120MB、启动慢 440~730ms**（自解压缓存常驻；2026-10-06 实测：827ms→1267/1555ms、常驻 WS 125.8→245.9MB）。08 §4「启动耗时优先于体积」+ 00 §0「体积是七维度末位」→ **默认不压缩** |
| `SatelliteResourceLanguages=en` | 去掉非英文附属资源程序集 | 实测省数 MB；`MessageBox` 按钮文本来自 `user32.dll`（系统语言），**不受影响**；应用自身 UI 文案走 `dependencies\resources\i18n`，**不受影响** |
| `DebugType=none` | 不产出 `.pdb` | 发布包不需要调试符号；如需线上排查可改 `embedded` |
| `InvariantGlobalization` | **保持 false** | 中文排序/日期必需 |

脚本组装最终目录（**2026-10-06 用户规格 · 交付根 = `dock++\Releases\`，两档分文件夹**）：

```
D:\AiAgent\OCproject\dock++\      ← 开发工作区（非交付物）
└─ Releases\
    ├─ 完整版\                      ← 本节产物（离线即用；§2b 为精简版）
    │   ├─ Cship.exe               ← x64 单文件产物（AssemblyName=Cship，默认压缩）
    │   ├─ Cship-x86.exe           ← x86 产物，**必须重命名**为 Cship-x86.exe（与 x64 并存）
    │   └─ dependencies\
    │       └─ resources\          ← 从 src\Cship\dependencies\resources 复制（i18n / icons，两架构共用一份）
    │       # config\ 不预置：程序首启在 完整版\dependencies\ 下自动生成
    └─ 精简版\                      ← §2b 产物
```

> 完整版是"纯净系统双击即用、完全离线"的那一档。**WPF 不支持运行时裁剪**
> （`PublishTrimmed` 会运行时崩溃；`InvariantGlobalization` 又为中文排序所必需），
> .NET 8 运行时 CoreCLR + WPF + BCL + ICU 是不可分割的整体——
> 压缩后的 63/58 MB 就是"离线即用"的正路下限，"需要哪个依赖保留哪个"在此档没有官方实现路径。
> 想要极小体积走 §2b 精简版。

> **交付目录里只有这三项**——"仅功能产品本身，无任何多余文件"；`dependencies\config\` 由**产品首次运行**在对应路径自行构建。
> 交付产物是构建结果，不进版本控制（`CShips\.gitignore` 已含 `Releases/`）；重新打包会**先清理**该目录再产出。
> **自包含要求**：`Releases\` 整体（exe + dependencies）复制到任意路径都能独立运行，交付与移植测试均以"整个 `Releases\` 目录"为单位。

要求：
- x86 产物**必须重命名**为 `Cship-x86.exe`（否则与 x64 同名冲突）；重命名后自测可运行（单文件宿主持有自身路径，验证一次即锁定流程）。
- `resources\` **只放一份**（`Releases\dependencies\` 下）供两个 exe 共用；`config\` **不带出开发期数据**（首启自动生成）。
  注意：批次十清理后源侧 `config` 已无残留，但脚本仍要显式排除，避免回归。
- 路径解析由 `Paths.DepsDir()` 负责（= exe 旁的 `dependencies\`，见 00 §5.3）——发布后**不得出现任何绝对路径**。
- 冒烟：分别双击两个 exe → 托盘出现 → 干净退出 → 日志无 `ERROR`/`WARN`；**两次运行必须共用同一份 config**（跨架构设置/图标顺序共享是本布局的核心收益，需实测确认）。
- **输出构建摘要到 STEP_LOG**：两架构 exe 体积、`dependencies\` 体积、构建耗时、首启耗时、开板态/空闲态内存。
- 脚本结束时若 `Releases\` 已存在，**先清理再产出**（避免旧文件混入导致体积/回归数据失真）。

### 2b. 发布脚本（**精简版**：framework-dependent + 引导器 · 首启联网获取运行时）

> 2026-10-06 用户新诉求："最大程度压缩体积，点开 exe 后跳出弹窗，从互联网获取 net8 等非本项目原创的内容，
> 进度条完成后方可使用，预留多个下载途径。"

组成与布局：

```
Releases\精简版\                        ← 初始合计约 4 MB（含 resources）
├─ Cship.exe / Cship-x86.exe            ← 引导器（net48 WinForms；同一 AnyCPU 程序集改名两次，
│                                          运行时按自身文件名区分 x86/x64 语义，双击入口）
├─ Cship.app.exe / Cship.app-x86.exe    ← 主程序（framework-dependent 单文件，约 1 MB）
└─ dependencies\
    ├─ resources\                        ← 预置（与完整版一致，两档共用同一套资源）
    ├─ runtime\{arch}\dotnet\            ← 引导器下载生成：基础运行时 + WPF 框架叠加解压（~160MB）
    │   └─ bootstrapper.log              ← 引导日志
    └─ config\                           ← 主程序首启生成（Paths 逻辑与完整版同一套，config 结构一致）
```

引导器（`src\CshipBootstrapper`，**新增项目**）职责与关键设计：

1. **运行时查找顺序**：本地 `dependencies\runtime\{arch}\dotnet`（此前下载的）→ 系统安装位置
   （`%ProgramFiles%\dotnet`，x86 看 ProgramFiles(x86)）→ 都没有才弹下载窗体。找到即启动主程序并退出；
   本地运行时注入 `DOTNET_ROOT_X64/X86`（.NET 6+ apphost 支持），系统运行时不注入（apphost 自己能找到）。
2. **下载内容 = 两个官方 zip 叠加**：官方没有"桌面完整根"zip——WindowsDesktop zip 顶层只有
   `shared\Microsoft.WindowsDesktop.App`（缺 apphost 启动必需的 `host\fxr`）；基础 runtime zip 提供
   `host\fxr + Microsoft.NETCore.App`。两包先后**覆盖式**解压到同一目录，构成完整 DOTNET_ROOT 布局。
3. **多下载源**（2026-10-06 实测三源均可直连，前源失败自动切换；窗体上"更换下载源"按钮可立即中断换源）：
   `builds.dotnet.microsoft.com` · `dotnetcli.azureedge.net` · `dotnetcli.blob.core.windows.net`。
   版本优先在线查询 8.0 线元数据（releases.json 的 `latest-runtime`），失败退回内置版本常量。
4. **免管理员、免安装、零系统残留**：下载到 %TEMP%、解压到程序目录，全程 asInvoker、不写注册表。
   引导器面向 **net48**（Win10/11 自带 .NET Framework 4.8），在没有 .NET 8 的机器上也能跑起来弹窗。
5. **排障开关**：环境变量 `CSHIP_FORCE_BOOTSTRAP=1` 强制跳过检测直接进下载窗（重装运行时/自动化测试用）。
6. 主程序缺失（安装包不完整）→ 错误弹窗并退出码 1；下载失败提示"改用完整版"。

发布参数：主程序 `--self-contained false -p:PublishSingleFile=true`；引导器
`dotnet publish src\CshipBootstrapper -c Release`（net48 产物本身就是单文件，约 157 KB）。

**实测（`build\_step8_lite.ps1` 端到端，含真实下载）**：双击 → 引导窗体 816ms → 在线查得 8.0.31 →
**下载 68MB + 双包解压 + 启动主程序共 8.9s** → 悬浮窗可见（WS 124MB，无自解压开销）；
二次启动引导器直接转发（不弹窗），主程序 2.0s 内启动。交付前需清掉测试生成的
`dependencies\runtime\` 与 `dependencies\config\`（重新变为"仅产品本身"）。

### 4. 发布体积与启动性能（本步新增硬指标）

| 指标 | 目标 | 实测方法 |
|---|---|---|
| 单架构发布体积 | 记录实际值（压缩后预期 60~90MB） | `du`/资源管理器 |
| **双击 → 托盘可见** | **< 3s** | 冷启动计时（压缩包解压是大头）；超了先关 `EnableCompressionInSingleFile` 再评估体积 |
| 首启到悬浮窗可交互 | < 5s | 日志时间戳 |
| 开板态内存 | < 250MB | `Get-Process` |
| 空闲 10 分钟内存 | 不单调增长 | 任务管理器 |
| 空闲 CPU | ≈ 0 | 任务管理器 |

> 若体积与启动耗时不可兼得：**以启动耗时为先**（用户体感 > 磁盘占用），在 STEP_LOG 记录取舍理由与两组实测值。

### 8. 源码仓库（`CShips\`，2026-10-06 用户规格）

> `dock++\CShips\` **就是 git 仓库**：交付的源码与测试资产在这里，开发工作区 `dock++\` 的临时脚本/素材/截图不进仓库。

```
CShips\
├─ .gitignore            ← 忽略 bin/obj/config/发布产物/测试临时物
├─ LICENSE               ← MIT
├─ README.md             ← 顶部居中：程序图标（assets\CShip.png）+ 名称 Cship；其余自述

├─ assets\               ← 图标源图（makeicon.ps1 的输入）

└─ docs\                 ← 产品设计简要说明 + 分步提示词（00~08 与 STEP_LOG.md）
```

- `git status` 必须干净；`bin` / `obj` / `dependencies\config` / 发布产物 / 测试临时目录均在忽略之列。
- 仓库内脚本仍以"仓库根"为相对基准（`build\build.ps1` 产出到 `..\Releases\`），从 `CShips\` 根目录调用即可工作。
