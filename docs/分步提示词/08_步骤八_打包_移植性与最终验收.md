### 1. 程序图标【原文 L74】

- `build\makeicon.ps1`：用 `System.Drawing`（PowerShell 可直接调）绘制 256px 三层错开半透明圆角方板（主题蓝白配色，GDI+ `GraphicsPath.AddArc` 画圆角）→ 导出 256/128/64/48/32/16 多尺寸 PNG → 组合为多帧 `.ico`（写 ICONDIR/ICONDIRENTRY 结构或用 `[System.Drawing.Icon]` 组帧）→ 存 `src\Cship\dependencies\resources\icons\cship.ico`。
- `csproj` `<ApplicationIcon>` 指向该 ico；托盘图标优先用该文件（01 的运行时绘制保留为回退）。
- **将来替换**：直接覆盖该 ico 重新 build 即可【L74】。脚本要**幂等**（重复运行结果一致、不残留中间 PNG）。

### 2. 发布脚本 `build\build.ps1`（双架构）

核心命令（每个架构一次）：

```powershell
dotnet publish src\Cship -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true `
  -p:PublishTrimmed=false `
  -p:SatelliteResourceLanguages=en `
  -p:DebugType=none `
  -o dist\x64
# win-x86 同理，-r win-x86 -o dist\x86
```

| 参数 | 作用 | 注意 |
|---|---|---|
| `PublishTrimmed=false` | **必须** | WPF 不支持裁剪，严禁改 `true` |
| `EnableCompressionInSingleFile=true` | 体积约降一半 | **会拖慢启动**（自解压），必须实测"双击到托盘可见"，见任务 4 |
| `SatelliteResourceLanguages=en` | 去掉非英文附属资源程序集（省数 MB） | 影响系统级对话框文案（如 `MessageBox` 按钮）；应用自身 UI 文案走 `dependencies\resources\i18n`，**不受影响**。若在意系统对话框中文，可去掉此参数（体积换体验，二选一并记录） |
| `DebugType=none` | 不产出 `.pdb`（省数 MB） | 发布包不需要调试符号；如需线上排查可改 `embedded` |
| `InvariantGlobalization` | **保持 false** | 中文排序/日期必需 |

脚本组装最终目录（**00 §5.2 交付布局 · 2026-10-05 用户规格**；脚本内可先在 `build\_publish\` 暂存，最终同步到仓库根）：

```
D:\AiAgent\OCproject\dock++\      ← 仓库根 = 交付根
└─ cship\                          ← 交付目录（自包含，整体可任意移动）
    ├─ Cship.exe                   ← x64 单文件产物（AssemblyName=Cship）
    ├─ Cship-x86.exe               ← x86 产物，**必须重命名**为 Cship-x86.exe（与 x64 并存）
    └─ dependencies\
        └─ resources\              ← 从 src\Cship\dependencies\resources 复制（i18n / icons，两架构共用一份）
        # config\ 不预置：程序首启在 cship\dependencies\ 下自动生成
```

> 交付产物是构建结果，不进版本控制（`.gitignore` 已含 `/cship/`）；重新打包会**先清理**该目录再产出。
> **自包含要求**：`cship\` 整体（exe + dependencies）复制到任意路径都能独立运行，交付与移植测试均以"整个 `cship\` 目录"为单位。

要求：
- x86 产物**必须重命名**为 `Cship-x86.exe`（否则与 x64 同名冲突）；重命名后自测可运行（单文件宿主持有自身路径，验证一次即锁定流程）。
- `resources\` **只放一份**（`cship\dependencies\` 下）供两个 exe 共用；`config\` **不带出开发期数据**（首启自动生成）。
  注意：批次十清理后源侧 `config` 已无残留，但脚本仍要显式排除，避免回归。
- 路径解析由 `Paths.DepsDir()` 负责（= exe 旁的 `dependencies\`，见 00 §5.3）——发布后**不得出现任何绝对路径**。
- 冒烟：分别双击两个 exe → 托盘出现 → 干净退出 → 日志无 `ERROR`/`WARN`；**两次运行必须共用同一份 config**（跨架构设置/图标顺序共享是本布局的核心收益，需实测确认）。
- **输出构建摘要到 STEP_LOG**：两架构 exe 体积、`dependencies\` 体积、构建耗时、首启耗时、开板态/空闲态内存。
- 脚本结束时若仓库根 `cship\` 已存在，**先清理再产出**（避免旧文件混入导致体积/回归数据失真）。

### 4. 发布体积与启动性能（本步新增硬指标）

| 指标 | 目标 | 实测方法 |
|---|---|---|
| 单架构发布体积 | 记录实际值（压缩后预期 60~90MB） | `du`/资源管理器 |
| **双击 → 托盘可见** | **< 3s** | 冷启动计时（压缩包解压是大头）；超了先关 `EnableCompressionInSingleFile` 再评估体积 |
| 首启到悬浮窗可交互 | < 5s | 日志时间戳 |
| 开板态内存 | < 250MB | `Get-Process` |
| 空闲 10 分钟内存 | 不单调增长 | 任务管理器 |
| 空闲 CPU | ≈ 0 | 任务管理器 |

> 若体积与启动耗时不可兼得：**以启动耗时为先**（用户体感 > 磁盘占用），在 STEP_LOG 记录取舍理由与两组实测值。
