### 4. 配置导出/导入格式【原文 L60-61；2026-10-05 适配当前设置项生态】

```text
# Cship 配置 v1
# 导出时间: yyyy-MM-dd HH:mm:ss
# 范围: settings 全键 + state.categories / state.iconOrder / state.removedItems / state.virtualItems；不含位置尺寸与图片本体
theme.mode=system
general.fps=60
personal.boardBg={"image":"","crop":null}        ← 嵌套值用单行 JSON
state.categories=[{...}]                          ← 收纳板布局：每项占一行 JSON
state.iconOrder={...}
state.removedItems=[...]
state.virtualItems=[...]
```

- **范围** = settings.json 全键 + 收纳板"用户可带走"的 state 键（分类/图标格序/移除名单/板内快捷方式）。
  **机器相关键刻意不含**：`dock.pos`、`board.size.*`、`board.pos.*`、`firstRunDone`——换机导入无意义。
- **键名映射（2026-10-05 修）**：state.json 里是**裸键名**（`categories`/`iconOrder`/`removedItems`/`virtualItems`），
  配置文件按上文写成 `state.<裸键名>`；`ConfigPort` 负责两处映射。旧实现直接拿 `state.categories` 读写 state.json，
  导出时读不到（静默跳过，导出文件里从来没有这两行）、导入时写进没有任何调用方读取的假键——**收纳板布局那一半从未生效**。
- **可导入键集合与导出对称**：00 §8 默认表 ∪ 当前 settings.json 实际持有的键 ∪ 上述 state 键。
  表外键（删功能留下的残留键、后续步骤新增的键）也随生态进出，无需改代码——旧实现只认默认表，
  表外键"导得出去、导不回来"，摘要恒报"忽略 N 项"。
- UTF-8；未知键忽略、非法值跳过并计数；解析后弹摘要（将应用 N 项/忽略 M 项/**被忽略的键名**），确认后全部热应用
  （settings 经 `Set` 广播即时生效；state 键由 `BoardWindow.ApplyImportedConfig` 重载：iconOrder/移除名单直接对账，
  快捷方式变化经一次 `RescanAsync` 纳入源集合）。
- 不含自定义图片本体（仅相对路径，缺失回退默认）。
- **形状/区间校验（2026-10-06 适配）**：除枚举白名单外，结构型键在导入侧逐键校验——
  `personal.dockCustom.opacity`（3 个数字）、`personal.dockCustom.images`（3 个字符串）、
  `personal.boardBg`（null 或含 `image` 字符串的对象）、`personal.boardOpacity`/`personal.boardBgOpacity`（数字）。
  结构非法 → 跳过并点名（`键名（值非法）`）；仅数值越界 → 夹回 0~100 后放行（不丢用户配置）。
  理由：这些键读取侧只会各自静默兜底，照单全收会得到"看起来导入了、其实什么都没变"的结果。

## 技术指引与坑

- 子项控件初始值必须从 `SettingsStore` 读取，禁止控件内再存一份默认值副本。
- 语言切换：各窗口/控件监听 `I18n.LanguageChanged` 重新赋值文字（WPF 无自动机制，需集中处理；可约定所有文字绑定走 `Tr` 的包装属性）。
- `WM_COMMAND 0x7402`：SHELLDLL_DefView 有时挂在 WorkerW 下，两条路径都查（07 步统一封装进 SystemBridge）。
- ColorPicker 的 HEX 输入要容错（#RGB/#RRGGBB/#RRGGBBAA），非法回退当前色。
