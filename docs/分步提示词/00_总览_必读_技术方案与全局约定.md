## 0. 项目理念（最高准则 · 2026-10-05 用户确立）

> 全项目的最高判据。任何技术选型、实现方式与验收结论，先过这一节再看其它条款。
> **用户体验是最终判据**——其余维度都是为它服务的，与它冲突的方案一律不采纳。

| 维度 | 落地要求 |
|---|---|
| **用户体验**（最重要） | 交互即时反馈不等待；窗口/动画不卡顿；**绝不丢用户数据**（删除走回收站、配置损坏自愈、退出必落盘）；异常自愈而非崩溃；文案双语齐全；行为可预期（无"点了没反应"） |
| 动画美学 UI | 所有跳跃式变化必须有过渡（§10 铁律 8）；时长/缓动统一引用 `AnimTuning`，不另立标准；材质与主题全局一致（含各级菜单） |
| 性能 | 启动到托盘可见 < 3s；常驻内存 < 250MB；空闲 CPU ≈ 0；拖动/动画期间**零抓屏**；大桌面（500+ 文件）滚动不卡 |
| 兼容 | Win10 1607+ ~ Win11 及未来版本；x86 / x64 / WOW64；混合 DPI 多屏；**零第三方依赖**（只用 .NET 8 内置 + P/Invoke）；不用 .NET 9+ API；**能力探测优先于版本号**，任何增强都必须可干净回退、绝不黑底 |
| 后开发 | 约定集中在 00 + STEP_LOG（决策编号可追溯）；路径唯一出口、设置唯一入口；静态事件成对退订；模块接口显式（如 `SquarePlate` / `MaterialBackground` 的既有 API 语义不得破坏） |
| 拓展 | 新增能力走**注册式扩展点**（材质通道、动画预设、主题字典、分类项），不改现有调用方；新增平台特性只加实现、不动回退链 |
| 体积 | 开发目录与发布产物双向控制（见批次十）：缓存一律设上限并 LRU；`config` 下可再生内容自动回收；发布参数（压缩 / 附属资源 / 调试符号）按体积与启动耗时权衡 |

**冲突裁决**：任一维度与**用户体验**冲突 → 用户体验优先；其余维度之间的取舍必须写入 STEP_LOG 并说明理由（先例：08 步"启动耗时优先于发布体积"，决策 226）。

## 3. 产品定义摘要

Cship：免安装的 Windows 桌面收纳工具（原始需求：`..\产品设计简要说明.txt`，下文【原文 L行号】指代其行号）。

- 双击主程序运行，常驻后台（任务栏隐藏图标区可见）【L2】
- 悬浮窗：三层半透明亚克力圆角方板错开叠加；悬停动画；单击后悬浮窗"拉开消散"，弹出收纳板【L3-6】
- 收纳板：陈列系统桌面全部文件（图标+名称），可调长宽、右键菜单、垃圾桶拖删、文件操作【L9-17】
- 分类页：**收纳板顶部横向分类按钮行**（2026-09-25 改版），默认 全部/软件/文件夹/文件，溢出折叠为"更多"下拉，右键移除/重命名，拖入图标加入分类，视图逻辑与主收纳板共用【L18-23】
- 设置：仿 macOS 风格，全局/显示/高级/个性化/关于【L25-72】
- 托盘菜单：偏好设置/复位/关闭/重启【L73】
- 全部 UI（含各级菜单）跟随"全局界面颜色"与"收纳板材质"【L75】

## 4. 技术选型（固定，不得更换）

| 层 | 选型 |
|---|---|
| 语言/框架 | C# 12 / **.NET 8 (LTS) / WPF**（`net8.0-windows`，`UseWPF` + `UseWindowsForms`，后者仅用于托盘 NotifyIcon 与屏幕枚举） |
| 系统集成 | P/Invoke（集中在一个 `SystemBridge.cs`）+ Microsoft.Win32.Registry + Microsoft.VisualBasic.FileIO（回收站删除） |
| 序列化 | System.Text.Json（设置/状态/配置导入导出） |
| 打包 | `dotnet publish --self-contained` **单文件**，双架构 `win-x64` + `win-x86` |

选型理由（Agent 不需复述，仅约束行为）：

- 32/64 双架构发布是 .NET 一等公民；x86 包可在 64 位系统运行（WOW64）。
- self-contained 把运行时全部打入 exe：**纯净 Win10/Win11 免任何运行环境，双击即用**【L2、L77】。
- 原生 Windows 能力（DWM 材质、SHGetFileInfo 图标、托盘、多屏、注册表、文件监视）最顺。
- WPF Storyboard/Easing 动画满足"丝滑"要求，渲染线程独立。

**发布策略（08 步执行，此处统一口径）**：唯一交付目录 `cship\`，内含 `Cship.exe`（x64）与 `Cship-x86.exe`（x86）两个单文件主程序，共用其下的 `dependencies\`（布局见 §5.2）。

├─ Cship.sln

### 5.2 交付布局（08 步产出 · 2026-10-05 用户规格）

```
D:\AiAgent\OCproject\dock++\      ← 仓库根 = 交付根
└─ cship\                          ← 交付目录（自包含，整体可任意移动）
    ├─ Cship.exe                   ← 64 位主程序（单文件 self-contained）
    ├─ Cship-x86.exe               ← 32 位主程序（与 64 位并存，靠文件名区分）
    └─ dependencies\               ← 依赖与配置（两个架构**共用同一份**）
        ├─ resources\              ← i18n / icons 等（保持外置可编辑）
        └─ config\                 ← 运行时生成：settings.json / state.json / iconcache\ / assets\ / logs\
```

**要点**：
1. **`cship\` 自包含**：`dependencies\` 就在两个 exe 旁边，整个 `cship\` 目录复制/移动到任意路径（含中文/空格、跨分区、换盘符）都能运行【L77】，不依赖任何外部位置。
2. 两架构 exe **同目录并存**（x86 产物重命名为 `Cship-x86.exe`），且**共用同一份 `config\`**：切架构不丢设置、不丢图标顺序（本布局相对旧"每架构各带一份 dependencies"的核心优势）。
3. 单文件 self-contained 已内嵌运行时，故 `cship\` 顶层只有两个 exe + 一个 `dependencies\`。

### 5.3 路径铁律

1. **全项目禁止硬编码绝对路径**。一切路径经 `core/Paths.cs`：
   - exe 目录 = `AppContext.BaseDirectory`（单文件发布下同样指向 exe 所在目录）；
   - **依赖根/配置根 = `exe目录\dependencies\`**（与 exe 同级）→ 整个 `cship\` 目录**自包含**，可整体复制/移动到任意路径；
   - 开发态：csproj 把 `dependencies\resources` 以 `CopyToOutputDirectory=PreserveNewest` 复制到输出目录，路径逻辑与发布态完全一致。
2. 用户配置/素材一律存 `dependencies\config\`，保证整个发行目录复制到任意位置（含中文/空格路径）都能运行【L77】。
3. 自定义背景图：选定后复制副本到 `config\assets\`（内容 hash 命名），删除源图不影响显示【L65】。

### 悬浮窗

| 参数 | 值 |
|---|---|
| 单板边长 | `display.dockSize` 56px（滑轨 40~96） |
| 三板错位偏移 | 6px；hover 增至 10px（250ms）；圆角 12px |

### 收纳板

| 参数 | 值 |
|---|---|
| 尺寸 | 默认 1334×806（2026-08-29 用户反馈按其截图量得，四方向默认统一；up 锚定后可见区域即约此值）；min 480×320；max=所选屏**完整边界**（可覆盖任务栏）；圆角 12px |

### 材质三档（06 步实现，此处统一口径）

> **渲染通道策略**：默认全平台使用**模拟通道**（窗口 `AllowsTransparency` 圆角 + 后方屏幕截图 + `BlurEffect` + 噪点 + 高光），保证 Win10/Win11 视觉一致且支持圆角；Win11 的 DWM 原生 backdrop（`DWMWA_SYSTEMBACKDROP_TYPE`）仅作可选增强，失败自动回退模拟通道。理由：`AllowsTransparency` 分层窗口与 DWM backdrop 互斥，且 Win10 无系统圆角。

| 材质 | 配方 |
|---|---|
| 亚克力 | α≈70%、轻噪点(64×64 平铺, opacity 0.04)、中模糊 |
| 模糊 | α≈50%、强模糊、无噪点 |
| 液态玻璃 | α≈55%+模糊+顶部 1px 内高光 `#66FFFFFF`+底部内阴影+边缘 24px 渐变 |

**界面颜色模式（`theme.mode`，06 步实现）**：`light`/`dark` 用对应调色板；`auto` 按本地时间 06:00~18:00 取亮、其余取暗；`system` 跟随系统主题；**`transparent`（原文 L28 新增）**=背景板近乎全透明（α≈8%，仅留极淡磨砂 + 1px 发丝描边勾勒边界），文字/图标取高对比浅色 + 加重投影以保证任意背景下可读，仍走模拟通道（不得依赖 DWM backdrop）。所有模式切换一律经 `ThemeFade` 300ms 过渡。

## 10. 行为铁律（安全与体验）

1. 删除一律进回收站（`FileIO.Delete*` + `RecycleOption.SendToRecycleBin`），绝不永久删除。
2. 隐藏桌面图标只切换显示状态，绝不移动/删除用户文件；程序退出时恢复显示。
3. 写注册表仅限 `HKCU\...\Run`（自启动）与读取主题键；其他一律禁止。
4. 单实例运行；第二实例唤起已有实例后退出。
5. 所有窗口响应 Esc（经 `ShortcutRouter`）；悬浮窗常驻，收纳板仅 Esc 或红点收起。
6. 日志写 `dependencies\config\logs\`，按天分文件，保留 7 天。
7. 全部 UI 文案走 I18n（zh-CN / en-US 双语齐全）。
8. **所有视觉上的跳跃式变化必须设计过渡动画**（原文 L79）：图标/内容的增删换位、面板与菜单开合、状态切换、按钮反馈、滚动、主题换装等，凡"跳变"可动画化者一律平滑过渡（时长与缓动统一引用 §7 动画表与 `AnimTuning`），不得瞬变；确实无法动画的（如物理边界硬约束）须在 STEP_LOG 记录原因。
