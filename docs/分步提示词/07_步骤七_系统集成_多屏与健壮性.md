## 任务

### 1. 开机自启动最终版【原文 L29】

**已落地**：`Autostart` 写 `HKCU\...\Run` 的 `"Cship"` 值 = `"<exe绝对路径>" --autostart`（`Environment.ProcessPath` 运行时解析，绝不硬编码）；`App.LaunchedWithAutostart` 已解析 `--autostart`。**待做**：
- 打包态与开发态**两种形态实测并记录**到 STEP_LOG（开发态 `ProcessPath` 指向 `bin\...\Cship.exe`，非 `dotnet run` 命令行——与 01 旧描述不同，以实测为准）。
- `--autostart` 静默启动语义确认：**不弹收纳板，仅托盘 + 悬浮窗**（复核启动链路）。
- 写键失败（组策略限制）→ 托盘气泡提示一次，且**开关 UI 状态回滚**为实际值。

### 2. 隐藏桌面图标最终版【原文 L33】

**已落地**：`SystemBridge.SetDesktopIconsVisible` 走 `Progman → SHELLDLL_DefView → SysListView32`，Progman 路径失败时遍历 `WorkerW` 兄弟层下钻 `SHELLDLL_DefView`，`SendMessage(WM_COMMAND, 0x7402)`；`DesktopIconsHidden` 跟踪真实状态（0x7402 是**切换**不是置位）；`App.OnExit` 恢复显示。**待做（本步核心）**：
- **崩溃恢复心跳**：`state.lastRunOk`（每 30s 写 true；启动先置 false、正常退出置 true）。启动时发现 `false` 且上次意图为隐藏 → **先强制恢复图标可见**，再按当前设置应用，并气泡告知。
- **桌面重建重放**：`HwndSource.AddHook` 监听 `TaskbarCreated`（`RegisterWindowMessage("TaskbarCreated")`；**返回值按进程缓存**）。资源管理器重启后重放隐藏意图。**钩子必须在窗口关闭时移除**（`RemoveHook`），否则 HwndSource 泄漏。
- 退出路径补全：`Application.Exit` 路径 + `ProcessExit` + `SessionEnding`（注销/关机）**三条都要**恢复显示并落盘。
- 主题跟随监听的重复订阅检查（06 已用 `SystemEvents.UserPreferenceChanged`，本步确认不重复挂）。

### 3. 多屏与屏幕选择【原文 L43】

**已落地**：`Screens.SelectedScreen()`（auto=光标所在屏 / 指定=按 `DeviceName` 匹配）；悬浮窗拖动/夹边、收纳板锚边均基于该屏。**待做**：
- **枚举信息增强**：`GetMonitorInfoW` + EDID（`WmiMonitorID`）解析型号名，显示"显示器N · 2560×1440 · DELL U2723QE"；**解析失败必须回退基础信息**（WMI 在部分环境不可用/慢，要有超时或异常兜底，绝不阻塞 UI）。
- **热插拔**：`SystemEvents.DisplaySettingsChanged` → 所选屏移除时自动回 `auto` + 悬浮窗复位主屏顶部居中 + 气泡告知；分辨率变化 → 悬浮窗/收纳板位置校验夹回。
- **混合 DPI**：PerMonitorV2 下拖动跨屏无跳变（用**每屏 DPI** 手动换算，勿依赖全局缩放）——`GlassWindow.DpiScaleX/Y` 已提供，核对所有物理/逻辑换算点都走它。
- **缓存**：`Screen.AllScreens` 底层是 P/Invoke，按 `DisplaySettingsChanged` 失效重取（批次九实测它是热点调用之一）。

### 8. 全屏前台窗口检测（**已定稿方案 B 并落地**，2026-10-05 用户裁决）

- **能力现状**：`SystemBridge.IsForegroundFullScreen(Screen)` 已实装——前台窗口 rect **完整覆盖所选屏 Bounds** 才算（最大化窗口 rect=工作区，天然不满足），并排除自身进程、桌面壳（Progman/WorkerW）、DWM cloaked 窗口。该能力同时服务 `App.OnHotkeyPressed` 的 Tab/Alt+Tab 决策。
- **原 medium 档用途作废**：00 §7 的"medium 档检测到全屏则隐藏悬浮窗"**不再适用**——悬浮窗自 2026-10-03 起恒定桌面级（`HWND_BOTTOM`），全屏应用天然盖在它之上，无需隐藏。`FloatingDock` 的 medium 档占位 API（`OnForegroundFullScreenChanged` / `ProbeForegroundFullScreen`）**已随本步删除**。
- **方案 B（已实现）**：置顶中的**收纳板 / 设置窗**在所选屏出现真全屏前台时**自动退层**（`Topmost=false`），全屏退出后按 `advanced.dockPriority` 恢复——避免置顶窗口压在全屏游戏/视频上。
  - 实现：`App.StartFullScreenWatch()`（1s `DispatcherTimer`，Background 优先级）→ `App.OnFullScreenTick()`；
    `BoardWindow.SetFullScreenRetreat(bool)` / `SettingsWindow.SetFullScreenRetreat(bool)` 承载退层与恢复，
    恢复一律回调各自的优先级落定方法（`ApplyBoardPriority()` / `ReapplyPriority()`），**不写死 `Topmost=true`**——low 档仍保持不置顶。
  - **防抖动约束（实现要点）**：tick 里"是否值得检测"的判定必须用**优先级档是否要求置顶**这个稳定事实，**不得用 `Topmost`**——退层后 `Topmost` 已是 false，用它判定会立刻走复位分支，与退层互相触发形成每秒抖动。
  - 开销：仅当"优先级档要求置顶 **且** 至少一个窗口可见"时才做 P/Invoke；不置顶档（low，当前默认）或窗口都关闭时零检测开销。
  - **强制置顶会话例外（2026-10-05 实机 bug 修复）**：退让只有在"用户没有正在主动要求置顶"时才是对的。`advanced.hotkeyForce`（默认 Alt+Tab）在真全屏前台下**强制开板并置顶**，这是用户此刻下达的显式指令——若退让监视照常判定，会在 ≤1s 内把刚提上去的 `Topmost` 抹成 false，板被满屏游戏盖住，观感=**出现即消失**（日志实锤：强制开板 03.599s → 退层 04.055s）。故 `App` 记一个 `_boardForceTopmost` **会话**标志：强制开板时置位、板隐藏时清除（`IsVisibleChanged`），会话期间 tick 直接挂起判定（`forceTopmostSession`）。会话结束（板关闭）后判定自动恢复，**不跨开板会话残留**；板若走普通链路（托盘/单击）重开，优先级照旧由 `advanced.dockPriority` 决定。
- **可选增强（未做，按需再加）**：`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` 即时反应替代 1s 轮询（当前最坏延迟 1s，全屏切换体感足够）。

## 技术指引与坑

- `Screen.AllScreens` / `WorkingArea` 是 WinForms 类型、**物理像素**；窗口 `Left/Top` 是 WPF 单位：物理 = WPF × DPI/96（`GlassWindow` 已有换算辅助，勿再手写一份）。
- `FileSystemWatcher` 的 `NotifyFilter` 至少含 `FileName|DirectoryName|LastWrite`；`IncludeSubdirectories=false`。
- 后台线程禁止直接触碰 WPF 控件（`InvalidOperationException: 调用线程无法访问此对象`），一律 `Dispatcher` 回调。
- `RegisterWindowMessage` 返回值按进程缓存；`HwndSource.AddHook` 的钩子在窗口关闭后**必须** `RemoveHook`。
- 原生进程枚举若启用：Toolhelp32 快照要**正确释放句柄**（`CreateToolhelp32Snapshot` → `CloseHandle`），这是批次九审计的高危点。
- 零第三方依赖：只用 .NET 内置（`System.Threading.Channels` 属 .NET 自带，可用）；不 `dotnet add package`。
